| 测试类型 | 接口功能测试、接口自动化、轻量性能基线、Web UI 冒烟 |

## 二、缺陷汇总

| 编号 | 标题 | 严重度 | 优先级 | 状态 |
|---|---|---|---|---|
| D-001 | 不存在商品返回 200 而非 404 | S3 | P1 | 新建 |
| D-002 | 购买量=库存被误判库存不足（边界值错） | S2 | P1 | 新建 |
| D-003 | 重复支付静默成功（无幂等） | **S1** | **P0** | 新建 |

D-003 为发布阻断项，必须在修复并回归通过后才可上线。

## 三、质量评估

- **主流程**（登录 → 加购 → 下单 → 支付 → 查询）链路通畅，状态流转正确
- **鉴权**：未登录/伪造 token 均被拦截，跨用户访问订单返回 404（未泄露他人数据）
- **金额计算**：0.01×3=0.03、1299+0.02=1299.02，无浮点溢出
- **风险集中区**：边界值校验（D-002）、幂等与状态机（D-003）

## 四、未覆盖与风险

| 项 | 原因 | 建议 |
|---|---|---|
| 并发下单库存超卖 | 单线程脚本未做压测 | 用 JMeter/locust 50 并发抢 5 件库存验证 |
| 支付回调异步一致性 | 无真实支付网关 | 接沙箱网关后补回调+对账用例 |
| 数据库层校验 | 无 DB 直连权限 | 增加 DB 断言：库存字段与订单状态落库一致性 |
| 兼容性/弱网 | 仅接口层 | 补 Chrome/移动端弱网（3G、丢包）场景 |

## 五、给开发的修复优先级建议

1. **P0** 支付幂等（D-003）—— 上线前必须修复
2. **P1** 库存边界（D-002）—— 影响可售库存，当版本修复
3. **P1** 404 语义（D-001）—— 随版本修复，可与前端确认兼容策略
