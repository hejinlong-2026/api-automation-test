## D-001 查询不存在商品返回 200 + data:null，而非 404

| 字段 | 内容 |
|---|---|
| 缺陷编号 | D-001 |
| 标题 | 【商品详情】查询不存在的商品 ID 时接口返回 200，前端无法区分“不存在”与“异常空值” |
| 模块 | 商品中心 / 商品详情 |
| 严重程度 | 一般（S3） |
| 优先级 | P1 |
| 发现版本 | v0.9.0 |
| 关联用例 | PROD-02 |
| 状态 | 已关闭 |

**前置条件**：服务正常，已登录。

**复现步骤**
1. 调用 `GET /api/products/NOT_EXIST_999`
2. 查看 HTTP 状态码与响应体

**实际结果**
```json
HTTP 200
{"code": 0, "message": "success", "data": null}
```

**预期结果**
```
HTTP 404
{"code": 404, "message": "商品不存在", "data": null}
```

**影响分析**
前端拿到 200 会走“成功”分支，把 `data=null` 渲染成空白页而不是“商品已下架”提示；
监控层面 404 与 200 的统计口径被打乱，商品下架率、失效链接率无法统计。

**建议修复**：资源不存在统一 404；如需兼容，业务码用非 0 值区分。

## D-002 加购数量恰好等于库存时被拒（边界值实现错误）

| 字段 | 内容 |
|---|---|
| 缺陷编号 | D-002 |
| 标题 | 【购物车】购买数量等于库存上限时提示“库存不足”，边界判断用了 `<` 而非 `<=` |
| 模块 | 交易 / 购物车 |
| 严重程度 | 严重（S2） |
| 优先级 | P1 |
| 关联用例 | CART-02 |
| 状态 | 已关闭 |

**复现步骤**
1. 商品 P002 当前库存 5
2. 调用 `POST /api/cart`，body = `{"product_id":"P002","quantity":5}`

**实际结果**：HTTP 400，`{"code":400,"message":"库存不足"}`

**预期结果**：HTTP 200，加购成功（数量 = 库存是合法场景，应为临界可售）

**影响分析**
用户买“最后 N 件”时永远提示库存不足，实际库存卖不出去。
这是典型边界值错误：`qty > stock` 校验写成了 `qty >= stock`。

**建议修复**：边界判断改为 `qty > stock` 才拦截。

## D-003 重复支付被静默接受，存在重复扣款风险

| 字段 | 内容 |
|---|---|
| 缺陷编号 | D-003 |
| 标题 | 【订单】同一订单连续调用支付接口两次均返回成功，无幂等控制、无 409 提示 |
| 模块 | 交易 / 支付 |
| 严重程度 | 致命（S1，资损风险） |
| 优先级 | P0 |
| 关联用例 | ORDER-04 |
| 状态 | 已关闭 |

**复现步骤**
1. 下单得到 `order_id`
2. `POST /api/order/{order_id}/pay` → 200，status=PAID
3. 再次调用同一接口

**实际结果**
```json
HTTP 200
{"code":0,"data":{"order_id":"OXXXX","status":"PAID","repeated":true}}
```

**预期结果**
```json
HTTP 409
{"code":409,"message":"订单已支付，请勿重复支付"}
```

**影响分析**
用户网络慢时连点两次“立即支付”，前端两次都收到成功，无法判断哪次真正扣款；
若对接真实支付网关（无幂等键 idempotency_key），会产生两笔实际扣款与一个订单，属资损级缺陷。

**建议修复**
1. 支付前校验订单状态，已支付返回 409；
2. 支付请求携带幂等键（order_id + 请求流水号），网关侧做去重；
3. 建议加分布式锁，防并发双写。
